Why modernize — business value & delivery status

  • Skills risk: COBOL/CICS expertise is scarce and retiring; Java draws from a large talent pool.
  • Run cost & lock-in: MIPS-based licensing and proprietary hardware give way to commodity cloud compute.
  • Agility: rigid batch windows become elastic, observable, CI/CD-ready Spring services.
  • Maintainability: a 19,254-line opaque COBOL estate becomes a layered, tested codebase.
  • Low risk: 100% behavioral parity preserved; the only intentional behavior change is BCrypt password hashing.

Onboarding — clean machine to running app

timeline title Developer onboarding path Clone : git clone the repository : cd carddemo-java Build : mvnw clean verify : 888 tests and 81.5% coverage Run : docker compose up -d : mvnw spring-boot run, local profile Verify : actuator health returns UP : sign-in and account view Extend : add an entity : add a batch job : add a REST endpoint
  1. Clone & build: git clone <repo> → cd carddemo-java → ./mvnw clean verify
  2. Start local stack: docker compose up -d (PostgreSQL, LocalStack, Jaeger, Prometheus, Grafana)
  3. Run the app: ./mvnw spring-boot:run -Dspring-boot.run.profiles=local
  4. Verify health: curl localhost:8080/actuator/health → {"status":"UP"}
  5. Integration suite: ./mvnw verify -Pintegration (Testcontainers)
  6. Extend: add an entity, a batch job, or a REST endpoint

Full clean-machine-to-running-app instructions, ports and pitfalls are documented in onboarding-guide.md.

# CardDemo Walking Skeleton (F-SKEL) — Blitzy Project Guide

## 1. Executive Summary

### 1.1 Project Overview

The **CardDemo Walking Skeleton (F-SKEL)** is a clean-room modernization of the legacy AWS CardDemo mainframe application into a contract-first, containerized microservice topology. It delivers eight Spring Boot 3 / Java 21 services (`auth`, `account`, `card`, `transaction`, `payment`, `useradmin`, `reporting`, plus a `bff` aggregator), a React 19 + MUI single-page UI that binds only to the BFF, an Oracle 23ai data layer managed by Flyway, and a `docker-compose` deployment unit. It is a **structural (topology) run**: success is defined by every seam building green and exactly **one** vertical tracer slice — an authenticated Card Detail read (UI → BFF → `card-svc` → Oracle) — running end-to-end, with all remaining business logic intentionally delivered as typed `[DEFERRED]` stubs. Target users are the platform/engineering teams who will build functional epics atop this validated foundation.

### 9.7 Example Usage & Troubleshooting

**Ports:** UI `3000→80` (nginx); `bff 8080`, `auth 8081`, `account 8082`, `card 8083`, `transaction 8084`, `payment 8085`, `useradmin 8086` (all container port 8080, local-dev override only); Oracle `1521`. `reporting-svc` publishes **no** host port (async job stub).

Common issues and resolutions:
- **Oracle slow first boot** (~14s+ to healthy): let `depends_on: service_healthy` gating do its job — do not bypass it; watch `docker compose logs -f oracle`.
- **Port already in use**: override the relevant `*_PORT` in `.env`.
- **Codegen drift** (`git diff` shows changes under `ui/app/api/generated`): rerun `npm run generate:api` and commit the in-sync client — the CI determinism gate enforces this.
- **`card-svc` integration test fails to start a container**: ensure the Docker daemon is running (`docker info`) — the test uses Testcontainers.
- **npm audit shows 3 high-severity findings**: these are build-only transitive dependencies (never in the shipped nginx bundle); do **not** run `npm audit fix --force` (it breaks the deterministic codegen). Track upstream instead.

### F. Developer Tools Guide

- **Backend build/test:** Maven reactor at the repo root aggregates all 8 service modules; `openapi-generator-maven-plugin` (generator `spring`, `interfaceOnly`) emits server interfaces into `target/generated-sources`.
- **UI codegen:** `@openapitools/openapi-generator-cli` (wrapping generator 7.23.0) generates the `typescript-axios` client from the frozen BFF contract into `ui/app/api/generated`; a determinism gate (`git diff --exit-code`) enforces in-sync commits.
- **Integration testing:** Testcontainers manages a real `gvenzl/oracle-free` container for `card-svc`'s `CardRealOracleReadTest`; requires a running Docker daemon.
- **Health & correlation:** every request-serving service exposes Spring Boot Actuator `/actuator/health`; a `CorrelationIdFilter` (`OncePerRequestFilter` + SLF4J MDC) propagates `X-Correlation-ID` across the chain.

### G. Glossary

| Term | Definition |
|------|------------|
| Walking Skeleton | A minimal end-to-end implementation of the target topology that builds green and runs one vertical slice, with all other logic stubbed |
| Tracer slice | The single fully-wired vertical path: UI → BFF → `card-svc` → Oracle → rendered Card Detail |
| BFF | Backend-for-Frontend; the thin aggregation service the UI binds to exclusively |
| SSoT | Single Source of Truth — here, the frozen OpenAPI 3.1 contracts |
| `[DEFERRED]` | Tag for functional epics scaffolded with zero implementation (out of skeleton scope) |
| Typed stub | A contract-conformant placeholder response (the correct outcome for non-tracer seams) |
| Health-exempt | `reporting-svc`'s status: builds green with an invokable job entrypoint but not held to start-and-serve / `service_healthy` |
| Identity PK | `GENERATED BY DEFAULT AS IDENTITY` surrogate key (seed-safe; avoids ORA-32795) |

# CardDemo Migration — Decision Log

This decision log is the single source of truth for every non-trivial decision made while migrating the AWS CardDemo application from COBOL / CICS / JCL to Java 25 LTS + Spring Boot 3.5.11 (the AAP §0.5.1-pinned version; see D-034 for the security-remediation transitive version overrides applied on top of the frozen 3.5.11 BOM). Each entry records the **decision**, the **alternatives considered**, the **rationale**, and the residual **risks**; per the user-specified *Explainability* rule this rationale lives here and is **never** duplicated in code comments, and any deviation from a literal COBOL interpretation is captured as an explicit row below. The COBOL baseline against which 100% behavioral parity is measured is the frozen legacy corpus at commit SHA `27d6c6f` — never the current `HEAD` of this repository.

| # | Decision | Alternatives Considered | Rationale | Risks |
|---|---|---|---|---|
| D-001 | Use `java.math.BigDecimal` (scale 2) for all COMP-3 / COMP monetary fields | `double` / `float`; `long` fixed-point cents | COBOL `PIC` clauses define exact decimal precision; `BigDecimal` with `compareTo` (not `equals`) reproduces `COMPUTE` / `ROUNDED` semantics identically and forbids any floating-point drift | Performance overhead vs. primitives, mitigated by confining `BigDecimal` strictly to monetary fields originating from a PIC decimal clause |
| D-002 | BCrypt password hashing for `USRSEC` users | Plaintext (preserve COBOL), Argon2, PBKDF2 | COBOL stores plaintext passwords; constraint C-003 explicitly permits the security upgrade while preserving the sign-on flow and login semantics | Existing plaintext credentials must be migrated via a hash-on-first-login pattern; legacy originals cannot be auto-rehashed without a known cleartext |
| D-003 | S3 versioned objects to replace GDG generation datasets | Local filesystem with rotation, PostgreSQL LOB columns | GDG semantics require generation numbering and retention; S3 object versioning across the three buckets (`carddemo-batch-input` / `-output` / `-statements`) is the native generation/retention equivalent | Requires LocalStack for local and integration testing; S3 versioning incurs storage cost |
| D-004 | SQS FIFO to replace the CICS Transient Data Queue `JOBS` | In-memory queue, Apache Kafka, RabbitMQ | CICS TDQ is point-to-point with strict sequential read; the SQS FIFO queue `carddemo-report-jobs.fifo` preserves identical ordering and submit-then-process semantics for the report bridge (F-011) | SQS FIFO has a 300 msg/sec throughput ceiling, which is sufficient for this workload |
| D-005 | Spring Batch for the JCL batch pipeline | Custom scheduler, Quartz, Temporal | JCL jobs are sequential batch steps gated by condition codes; Spring Batch provides native Job / Step / Flow sequencing, restartability, parameters, and condition evaluation | Learning curve for the Step / Job / Flow abstractions |
